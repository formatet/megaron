## Result and implementation

D2 reserves the pre-answer map before requesting its changed map. `beginOmen` filters out already known tiles and duplicates, orders new hexes from the find outward, and waits 300 ms before the first reveal. `omenMap` releases the server's saved tile outcomes at 300 ms steps. While waiting it retains each tile's actual prior fog (including absent tiles), rather than drawing any replacement. At zero it returns the exact original tile array. That array remains stable between steps. All regular map fetches (bootstrap, refresh and naming) now enter through `map_data.acceptMapTiles`, so polls cannot bypass the pending mask. A failed or superseded request is discarded safely; an empty/known patch keeps ordinary map refreshes without an animation. Camera focus/zoom and the existing sound remain as before.

The only omen paint is green. Its integer pixel mask uses the normal raster's `markHexAt` ownership, so warped borders do not spill onto a known neighbour. Mask spans are cached per hex/camera/tile-array for fade frames; changing a tile array invalidates them. Regular-hex fallback remains available with `markraster=0`. No terrain shader, seed, warp, fog colour, raster bake formula or persistent discovery rule changes. Only affected tile signatures require rebaking at a reveal step; fade frames never replace tile arrays. The mask is a green highlight, not a fog replacement.

D1's existing production rule remains: a covered fishing ground yields no fish, and its placed workers remain. Web Food and Keryx city/status now say “its fishers stay but catch nothing while it stands”; both fishing and storms Codex articles explicitly say placement remains and fishing resumes after departure. The DB test snapshots every placement's ordinal, target, coordinates and good, compares exact snapshots during and after the storm, and checks rates decrease and then return to calm.
